# MVP plan

Working document; update as milestones finish. Specs and design live in `docs/`.

Assumptions: one node manages many disks (identity file per disk: cluster, node, disk ID); public embedding API in package `node` (`Start`/`Stop`, `Alarms`, `Metrics`; design-notes §15); catalogue has PostgreSQL (production), SQLite (tests/dev only) and in-memory fake implementations behind one interface and one contract suite.

Notes
- 1 and 2 can run in parallel after specs are approved; 3 can run alongside 4 and 5. Milestone 7 carries the most risk.
- Milestone 10 needs a running store: it can start as soon as `cmd/store` runs a single node. Open: whether a thin `store node` (flags, signals, identity/db init) is pulled ahead of milestone 7 so single-node numbers arrive before the simulator work.
- Milestone 6 precedes the simulator so the node's shape (per-disk FS, `Deps`) is fixed before `sim/` drives it.
- SQLite cannot mimic PostgreSQL advisory locks or `SKIP LOCKED`; lease semantics must rest on plain transactions so all three implementations pass the same contract suite. SQLite is never a production catalogue.
- Open: listener ownership (node-owned vs host-mounted `Handler()`), settled in milestone 6.
- Decided 2026-11-05: PUT is fully buffered under the memory budget (sha256 sits in region A before the payload; buffering also enables parallel and atomic writes; revisit only if the size cap is lifted). GET streams and aborts the connection if payload_CRC fails (optimistic, fast in the normal case). Erasure writes plain zeros (no hole-punching), head first (format-v1 §7), one fsync per volume per batch, and the erase RPC never carries the zeros. Header CRC is verified before erasing.
- Decided 2026-11-05: crash model is "any subset of unsynced writes survives, torn at 512 B sectors" (`Mem.Crash`, `CrashAny`); names need `SyncDir` (ext4/XFS). Recovery of an open volume = longest valid prefix, stop at the first invalid record; no longest-replica replication (seal at the minimum committed length, retry on a new volume); `format.Resync` is for tooling only. Details in `docs/disk.md`.
- Decided 2026-11-05: `volume/` seals with seq = last prefix seq + 1 (may reuse a discarded tail seq: the seal is never encrypted and a sealed volume never gets appends); a failed `Writer` is dead, never retried. `Create` publishes the header atomically. Plan and CLAUDE.md: update `mvp-plan.md` with every milestone-moving commit.
- Decided 2026-11-05: `.idx` exists for sealed volumes only; no tail scan, because the restart rule already forces a full pass over each open volume. A bad or stale `.idx` is rebuilt, never an error.
- Approved 2026-11-05 (human gate, milestone 4): seal seq = last prefix seq + 1, even if it equals a discarded tail record's seq.
- Decided 2026-11-05 (milestone 5): `.nidx` follows design-notes §7 with two refinements: every 4 KiB bucket carries its own CRC (255 slots + trailer), so a flipped bit is a detected bad index and never a silent miss that would serve an older version; header padded to 4 KiB so buckets are page-aligned. The file is a pure function of (volume ID, entry set), so scrub can compare a rebuild byte for byte. A name mismatch on a candidate is a fingerprint collision (skip); any other mismatch is a stale index (rebuild once, retry). Erased candidates are skipped; the erasure list stays the node's job. The handle cache has no goroutine: the owner calls `CloseIdle` from its ticker. `nameindex.Clock` is a minimal injected interface; unify when a shared Clock exists. Added `volume.ReadHeadAt` and `volume.ErrNameMismatch` for this.
- Decided 2026-11-05 (milestone 3, confirmed by reviewer): leases use the injected clock, not database time (safety rests on lease generation + volume epoch fencing); two-phase seal (`BeginSeal` bumps the epoch, `FinishSeal` records it); permanent per-shard rows hold lease, generation and `next_volume_number`; `DeleteBucket` of an unknown bucket is `ErrBucketNotFound`; times are Unix milliseconds, IDs lower-case hex text; one portable migration set serves PostgreSQL and SQLite and one `sqlcat` implementation serves both. Added `clock/` (Clock interface + Fake; nameindex now uses it).
- Open items, milestone 3 (2026-11-05): (a) done: human review passed 2026-11-05; (b) decided 2026-11-05: `make check` does not start PostgreSQL; it expects one (`make pg-start`, `STORAGE4_TEST_PG_DSN`), and the PostgreSQL halves of the contract and `db` tests are skipped when none is configured; (c) testcontainers-go fallback in `db/dbtest.OpenPostgres` (start a container when `STORAGE4_TEST_PG_DSN` is unset and Docker is available) — scheduled below, needed by the higher-level automated tests; (d) `store db init|migrate|status|verify|bootstrap-sql` CLI wiring (library is done; milestone 9) and `bootstrap-sql`; (e) CI job rejecting edits to released `db/migrations/*.sql`, `db/schema/*.txt` and `format/testdata/` (still no CI config); (f) `Verify` covers tables and columns only, not constraints or indexes; (g) failover runbook command to bump `catalogue_meta.incarnation` (no `db` operation yet); (h) catalogue outage mapping to `ErrUnavailable` is heuristic (network/EOF/bad connection) and untested against a real PostgreSQL outage; (i) `RestoreBucket` (state `restored`) and bucket keys have no API yet.
- Decided 2026-11-05: binary versions are SemVer `major.minor.build+hash[.dirty]` from git tag `vMAJOR.MINOR` (build = commits since the tag, hash = 8 hex digits), computed by `scripts/version.sh` and passed with `-ldflags -X main.version` (`make build`, `make version`; `RELEASE=1` fails without a reachable tag). Informational only; schema version and compat level are integers. Open: `cmd/store` must declare `version`, pass it to `node.Start` and `db.Tool.AppliedBy` (`version@host`) (milestone 9); tag `v0.1` (or the first real version) before the first release build; release builds need full history and tags.
- Approved 2026-11-05 (human gate, milestone 3): migration `0001_initial.sql` and its schema snapshots (`db/schema/*-0001.txt`). From now on they are released artefacts: never edited, add `0002_…` instead.
- Approved 2026-11-05 (human gate, milestone 3): the `Catalogue` interface and the lease/volume-number/epoch SQL in `catalogue/sqlcat`.
- Scheduled: testcontainers-go (approved dependency) goes into `db/dbtest.OpenPostgres` as a fallback behind the local DSN, before the first higher-level automated test that needs PostgreSQL (node in-process e2e, milestone 6; L3/L4 later). Local PostgreSQL stays the default in agent sessions, which are already in a container (CLAUDE.md, Testing layers).

- Decided 2026-11-05 (milestone 6): dedup is "identical" only if sha256 **and** metadata bytes equal the latest version's (metadata compared after a sha256 match, by reading region A); a metadata change with identical content stores a new version; ETag stays the file's SHA-256. `docs/api.md` and design-notes §9 updated (spec not yet considered permanent). A striped per-name lock (256 stripes) covers lookup through ack, because retries can overlap. Defaults: lease TTL 30 s, memory budget 256 MiB, default S=4, open-volume cap 1 GiB / idle 1 h / 64 volumes. `DELETE /b/{bucket}/{name}` returns `501` until milestone 8; bucket delete is in milestone 6. Listener: `Handler()` always, optional `ListenAddr`.
- Open for review, milestone 6 (`docs/node.md`): `node-counter` file on every disk; `clock.Clock.After` and group commit without a window; fewer than three usable disks means `503`; `nameindex.Store.Lookup` must report erased candidates (milestone 8).
- Decided 2026-11-05: "ordinal" is renamed **volume number** (`volume_number` in the header, columns and Go identifiers `VolumeNumber`): the volume's position among its (bucket, shard)'s volumes, assigned by the catalogue; versions order by (volume number, seq). The on-disk bytes are unchanged, so golden files stand. By the reviewer's explicit decision, the frozen `0001_initial.sql` and its schema snapshots were edited in place (no deployment exists yet); the freeze applies from the first real installation.
- Milestone 6 implemented 2026-11-05 (`node/`: Start/Stop, HTTP API, shard leases, group-commit open volumes, seal/recover, name locks, memory budget, alarms/metrics). 20+ tests run on mem, SQLite and PostgreSQL catalogues, including crash recovery (`Mem.Crash`), replica failure (fault injection), volume rotation, restart and goroutine joins. Added `clock.Clock.After` (and `Fake.After/Waiters`), `db/dbtest.Catalogue`. Resolved the same day: `Cluster.Goodbye` (clean shutdown frees the node ID), heartbeat input validation mirrored in the fake with a contract test, and replica fallback on corrupt reads. Remaining before milestone 6 closes: code review (load tests moved to milestone 10). The testcontainers fallback is skipped for now (decided 2026-11-05): the local PostgreSQL stays the only L2 backend until later.
- Future (noted 2026-11-05): disk management. A disk that fails an append or a verified read should go read-only in the catalogue automatically and raise an alarm; today the node only avoids it for 10 minutes. Rule: every CHECK constraint reachable through the `Catalogue` interface needs a contract test, so the fake cannot drift from SQL.
- Decided 2026-11-05 (supersedes the earlier "load-test before closing milestone 6"): `node/` is a library, not a runnable store, so load testing moves to milestone 10 (client tools against a running store). Measure there: fsync cost per append and the effect of group commit, p50/p99 latency, throughput, memory-budget `503` behaviour, restart/seal time with large open volumes, `.nidx` handle use, goroutine and memory growth. The numbers set the group-commit window, open-volume size cap and memory budget defaults; until then the current defaults stand. The testcontainers fallback stays deferred.
- Decided 2026-11-06 (milestone 6 review): (1) an unreadable newest volume makes lookups *uncertain* instead of falling through to an older version: reads `503`, unconditional PUT proceeds, conditional PUT `503`, critical alarm; a sealed volume with zero records is skipped; corrupt-copy exclusion is per (disk, volume) (`docs/node.md`, "Unreadable volumes"). (2) `node-counter` is best effort: usable once on one disk, `503` only if no disk takes it; startup still takes the max over disks and the catalogue. (3) GET holds back the last chunk until the payload CRC verified, so an abort is visible to the client (before, the abort came after the full `Content-Length` and looked like success); the record is released on abort. (4) `n.meta` race fixed (incarnation tracked separately). Tests in `node/degraded_test.go`.
- Approved and done 2026-11-06 (milestone 6 review, seal logic): pending seals (a volume whose seal cannot complete stays readable and dedupable, retried from `tick`, lease kept; docs/node.md "Seals that cannot complete"); a volume is never recorded as empty when its replicas are readable but unsealable (`Start` fails with `errNoReplicaSealed` in that case); one seal check per seal so independently sealed replicas are byte-identical; `SealFile` fsyncs when it finds the replica already sealed. A pending seal whose volume the catalogue already sealed (`ErrVolumeSealed`, e.g. `FinishSeal` committed but its answer was lost) completes on the next retry (test `TestPendingSealAlreadySealedByCatalogue`). Not covered: lease loss with an open volume (milestone 7). Open: `create replica` failure when opening a volume returns 500, should probably be 503 or retry on another disk set; constant-time bearer token comparison; memory budget ignores buffer doubling in multipart parsing.
- Open issue (2026-11-07, alarms and events; retrofit once the implementation settles, not before): only 3 of the 7 alarm IDs are ever cleared (`catalogue-unavailable`, `memory-budget-exhausted`, `seal-pending`); `replica-unavailable`, `shard-lease-lost`, `disk-excluded` and `index-rebuilt` stay raised until restart. `replica-unavailable` is one ID shared by conditions with different lifetimes (append failed, corrupt copy on GET, volume without readable replica, fewer than 3 usable disks, replica creation failed, seal failed). Direction decided: (1) **events** are a first-class second channel next to alarms, for things that happened (corrupt copy served around, replica failed an append, index rebuilt, seal retried); (2) **alarms** are states, each ID names one condition with a documented clear point, split where lifetimes differ; (3) **severity follows rate**, not a fixed level: a single occurrence is an event or Info, repeats within a window escalate to Warning, then Critical (thresholds and windows injected via Config and evaluated on the injected clock). Open: the event interface (name- and metadata-free, like `Alarms`), the escalation rule and where its state lives (per node, in memory), which clear points depend on later milestones (repair and gone volumes: 8; disk read-only state: "Future" above; lease handover: 7), and a test per alarm that raises the condition, removes its cause and checks the clear. Until then the uncleared alarms are documented as cleared by operator action or restart.
